# 文件搜索分层查询优化

日期：2026-09-17
当前步骤：Complete

## 目标

在保留单字符搜索的同时，避免单字符触发文件名和路径的任意子串全表扫描；对多字符搜索优先返回精确及前缀结果，仅在不足 30 条时逐层补充包含匹配。

## 已确认行为

- 单字符：仅搜索文件名精确/前缀匹配。
- 两个及以上字符：精确匹配、文件名前缀、文件名包含、路径包含，逐层补足 30 条。
- 各层结果去重，保持层级优先级。
- 前端普通文件搜索防抖调整为 80ms。
- 数据库 schema 初始化留在应用启动，普通搜索连接不再重复执行初始化。

## 修改范围

- `src-tauri/src/utils/database.rs`
- `src-tauri/src/api/explorer.rs`（仅在调用接口确有需要时）
- `src/App.jsx`
- 针对查询分层和去重的 Rust 单元测试

## 验证

- Rust 格式检查与相关单元测试通过。
- 前端构建通过。
- 审查 SQL：单字符查询不得包含 `%keyword%` 路径扫描；多字符按结果不足逐层查询。

## 非目标

- 不引入 FTS5。
- 不重构应用搜索、插件搜索或索引生成流程。
- 不覆盖工作区内已有的其他未提交修改。
