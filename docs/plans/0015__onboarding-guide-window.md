# 四页新手向导独立窗口

日期：2026-09-30  
当前步骤：Complete

## 目标

新增一个四页的新手向导窗口，用静态示例介绍 Lark 的快捷键、搜索方式和主要功能组件。向导不监听、判断或验证用户在主窗口中的真实操作，只提供“上一步 / 下一步 / 跳过 / 开始使用”等显式按钮。

向导使用独立 Tauri Webview 窗口，不作为主窗口 Modal。首次自动展示期间主窗口默认隐藏，应用后台初始化继续运行；用户可以随时通过快捷键或托盘唤醒主窗口，完成、跳过或关闭向导后确保主窗口显示。应用设置中重新打开向导时不隐藏或阻塞主窗口，也不会重置首次启动状态。

## 关键假设与待确认边界

1. **完成状态字段采用 `onboarding_completed: bool`，默认 `false`。** 缺少该字段的旧配置也会按 `false` 处理，因此功能发布后，现有用户升级时也会看到一次向导。若只允许全新安装自动弹出，需要额外区分“旧配置升级”和“新配置创建”，不能仅依赖 `#[serde(default)]`。
2. **“跳过”“开始使用”和向导内的关闭按钮都视为已处理。** 三者都先持久化 `onboarding_completed = true`，保存成功后再关闭窗口，避免用户每次启动都被重复打扰。
3. **设置页重新打开不修改完成状态。** 它只直接打开窗口；关闭后下次启动仍不会自动弹出。
4. **重新打开时从第 1 页开始。** 完成或跳过后销毁向导 Webview，而不是长期隐藏，以释放资源并自然重置页码。
5. **快捷键示例优先显示当前配置值。** 向导只读取 `get_app_settings`，不注册键盘监听、不要求用户实际按键；读取失败时显示平台默认示例，不阻止继续浏览。

以上第 1 项是唯一会影响现有用户升级体验的产品决策；本计划推荐“所有用户在该功能首次发布后展示一次”，因为实现最简单且与“新增初始化变量”的语义一致。

## 第一性原理与方案选择

### 必须满足的约束

- 独立窗口：向导不依赖主窗口 React 状态；首次展示只控制主窗口初始可见性，快捷键和托盘仍可唤醒主窗口；设置页重开仍与主窗口并行。
- 非阻塞：不使用父子 Modal、同步等待用户完成、主窗口遮罩或暂停应用后台任务；首次向导期间也不禁止快捷键和托盘入口，用户可以边看边试。
- 无行为监听：不监听全局键盘、主窗口查询词、面板切换、组件打开或快捷键是否真的执行。
- CSS 隔离：向导样式既不能污染主窗口，也不能被主窗口的 `App.css`、设置页 `createGlobalStyle` 或通知样式意外覆盖。
- 状态可靠：只有明确跳过、完成或关闭且配置保存成功后，才认为首次向导已处理。

### 方案比较

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 在主窗口中增加 React Modal | 文件少、实现快 | 会占用主窗口状态和焦点，违背独立与非阻塞要求 | 不采用 |
| 复用 `index.html?window=guide`，在 `src/main.jsx` 静态导入向导 | 类似当前通知窗口 | `src/main.jsx` 当前静态导入 `App` 和通知组件，`App.css`、`notification.css` 含 `html/body/#root` 等全局选择器；向导 CSS 也可能进入其他窗口 | 不推荐 |
| 在现有入口中改成按查询参数动态导入所有窗口 | 可解决共享 CSS | 会同时改造主窗口和现有通知启动路径，扩大回归范围 | 暂不采用 |
| **新增独立 `onboarding.html` + 独立 React 入口** | CSS 和依赖天然分包，不必改现有主窗口/通知入口，隔离最强 | Vite 需增加多页面构建配置 | **推荐** |

## 窗口与生命周期设计

### 窗口属性

建议窗口标签为 `onboarding-guide`，URL 为 `onboarding.html`：

- 固定尺寸约 `860 × 620`，不可调整大小；小屏幕按工作区尺寸做上限保护。
- `decorations(false)`，由向导提供独立标题栏、拖动区域和关闭按钮。
- `transparent(false)`、`shadow(true)`，避免透明窗口的合成和可读性问题。
- `always_on_top(false)`；首次展示时主窗口默认隐藏但可被快捷键或托盘唤醒，设置页重开时两者仍是并列的非模态窗口。
- `skip_taskbar(false)`，防止向导失焦后无法找回。
- 主窗口配置为启动时默认隐藏；`onboarding_completed == false` 时只显示并聚焦向导，完成后再显示并聚焦主窗口，避免启动闪现。
- 首次向导期间不屏蔽唤醒、剪贴板、文件跳转快捷键和非退出托盘入口；应用后台初始化、索引和通知管理继续运行。
- 设置页主动重新打开时不隐藏主窗口，并允许向导调用 `set_focus()`，因为这是用户明确触发的操作。
- 向导创建或调度失败时取消首次引导门控并回退显示主窗口，避免应用只剩托盘且无法唤回。

### 创建时机

不在每次启动时预创建隐藏 Webview。启动读取配置后：

- `onboarding_completed == false`：保持主窗口默认隐藏，在 Tauri `setup` 主体初始化后异步创建并聚焦向导；快捷键或托盘仍可显示主窗口，完成后确保主窗口显示。创建或调度失败时回退显示主窗口，不能导致应用不可达。
- `onboarding_completed == true`：不创建向导并正常显示主窗口，不承担额外 Webview 内存和启动成本。
- 设置页调用打开命令：按需执行幂等的 `ensure_onboarding_window`；已有窗口则显示、居中并聚焦，没有则创建。

这里复用通知窗口的核心思想——由 Rust 管理独立 Webview 的唯一实例——但不照搬“每次启动都预创建”和“右上角通知栈定位”。

### 关闭与完成

- 前端点击“跳过”“开始使用”或关闭按钮时调用统一命令 `complete_onboarding`。
- Rust 先写入 `onboarding_completed = true`，成功后关闭 `onboarding-guide` 窗口。
- 保存失败时窗口保持打开，页面显示错误；不得用“先关窗口、后台尝试保存”的方式制造重复弹出。
- 多次点击打开按钮必须复用同一个 label，不创建重复窗口。

## 四页内容

### 第 1 页：呼出、输入、执行

- 使用当前 `hotkeyAwaken` 展示“呼出主窗口 → 输入应用、文件或关键词 → Enter 执行”的基础路径。
- 配合静态搜索结果示意，优先回答“这个窗口怎么打开、输入后怎么用”。
- 明确用户可以边看边试，但向导不监听、不验证，也不限制真实操作。

### 第 2 页：文件搜索与结果快捷操作

- 文件搜索有两种入口：直接输入关键词；或在主搜索框为空时按 `Tab` 进入文件搜索。
- `Enter` 打开当前结果。
- `Alt+Enter` 打开应用或文件结果所在的文件夹。
- `Alt+1～9` 快速选择当前可见结果中对应编号的项目。
- 向导中的组合键必须直接写作真实的 `Alt`；不得把主窗口现有的 `⌘` 视觉提示一并修改。

### 第 3 页：快捷入口与文件选择框跳转

- 使用当前 `hotkeyClipboard` 展示如何直接打开剪贴板历史。
- 使用当前 `hotkeyFileJump` 展示完整场景：先在资源管理器查看目标目录，再打开“打开 / 另存为”文件选择框，最后按快捷键跳转。
- 文案必须说明：跳转目标是“最近一次处于前台的资源管理器目录”，不是最近搜索结果、最近打开文件或任意历史目录。

### 第 4 页：内置组件与组件库

- 待办事项、周报、备忘录和 Hosts 作为开箱即用的内置组件展示，可直接搜索组件名称打开。
- “组件库”单独作为插件列表与配置页面说明：查看已安装插件、启用/停用和填写配置、开发或编辑自定义插件。
- 不得暗示内置组件需要在组件库中安装或开启。

最终按钮为“开始使用”；仍保留“上一步”。不在向导内直接切换主窗口面板，避免引入跨窗口导航和主窗口状态耦合。

## CSS 隔离策略

1. 新增独立 HTML 构建入口 `onboarding.html`，它只加载 `src/onboarding/main.jsx`。
2. 向导入口不导入 `src/App.jsx`、`src/App.css`、`src/notification/*`、Ant Design 全局样式或设置页 `createGlobalStyle`。
3. 样式文件仅为 `src/onboarding/onboarding.css`，类名统一使用 `onboardingGuide-` 前缀。
4. 即使独立页面允许设置 `html/body/#root`，仍将组件样式限定在 `.onboardingGuide` 根节点下，避免未来入口合并时产生泄漏。
5. 不复用主窗口 CSS 类名；共享颜色通过向导自己的 CSS 变量定义，不把变量写到主应用 `:root`。
6. `vite.config.js` 使用多页面 `rollupOptions.input` 显式包含 `index.html` 和 `onboarding.html`，保证生产包不会遗漏向导页面。

选择独立 HTML 而不只依赖 CSS Modules，是因为 CSS Modules只能隔离类名，不能阻止主入口中已有的全局 `html/body/#root/*` 规则进入同一个 Webview 构建入口。

## 配置设计

在 `BaseConfig` 增加：

```rust
#[serde(default)]
pub onboarding_completed: bool,
```

并增加窄接口：

- 启动阶段直接读取已经加载的 `BaseConfig.onboarding_completed`，不增加重复读取接口。
- `save_onboarding_completed(completed: bool) -> Result<()>`：只更新该字段并原子保存配置。

不把该字段塞进现有 `save_setting_data` 的完整应用设置提交中，原因是向导完成是独立生命周期；设置页保存快捷键或剪贴板配置时不应意外覆盖它。

## 后端命令与函数

在 `src-tauri/src/main.rs` 增加：

- `ensure_onboarding_window(app, focus)`：幂等创建或显示窗口。
- `open_onboarding(app)`：设置页调用，忽略完成标志并主动显示。
- `complete_onboarding(app)`：保存完成状态后关闭窗口。
- 必要时增加纯函数计算窗口尺寸/位置，便于单元测试；优先使用 Tauri `center()`，避免复制通知窗口右上角定位算法。

这些命令加入 `tauri::generate_handler!`。使用一个进程内原子状态限定“首次向导进行中”的短生命周期，不增加事件转发、轮询线程或新的 Tauri managed state。

## 设置页改动

在 `src/panels/settingComponent.jsx` 的“应用设置”页增加独立的“新手向导”卡片：

- 文案：可重新查看快捷键和主要功能介绍。
- 按钮：“重新打开新手向导”。
- 点击后调用 `invoke("open_onboarding")`。
- 调用失败复用现有 `settingNotice` 显示错误。
- 不提供“重置首次状态”开关，不把重新打开与应用设置的“保存设置”按钮绑定。

## 计划修改范围

- `onboarding.html`：独立 Vite 页面入口。
- `vite.config.js`：增加 `index.html` 与 `onboarding.html` 多页面输入。
- `src/onboarding/main.jsx`：向导专用 React 挂载入口。
- `src/onboarding/OnboardingGuide.jsx`：四页内容、页码状态和按钮逻辑。
- `src/onboarding/onboarding.css`：完全独立的向导样式。
- `src-tauri/src/config/config.rs`：完成状态字段、默认值、读写函数和配置兼容测试。
- `src-tauri/src/config/mod.rs`：导出向导配置接口。
- `src-tauri/src/main.rs`：独立窗口创建、首次调度、打开/完成命令及 handler 注册。
- `src/panels/settingComponent.jsx`：重新打开入口。
- 本计划与对应 chronicle。

不需要修改 `src/App.jsx`、`src/main.jsx`、`src/App.css` 或现有通知组件；这也是降低回归风险的关键边界。

## 实施步骤

### 阶段 1：配置和状态语义

1. 增加 `onboarding_completed` 字段，Windows/macOS 默认配置均为 `false`。
2. 增加独立读取和保存函数。
3. 补充旧配置缺字段反序列化测试。
4. 明确跳过、完成、关闭共用同一持久化边界。

### 阶段 2：Rust 独立窗口

1. 实现 `ensure_onboarding_window`，用固定 label 保证单实例。
2. 实现自动展示、设置页重新打开和完成关闭命令。
3. 启动时只在未完成状态下异步调度窗口创建；错误降级为日志。
4. 注册 Tauri 命令，并仅在首次向导生命周期内控制主窗口可见性；不改通知 manager。

### 阶段 3：独立前端入口

1. 新增 `onboarding.html` 与 `src/onboarding/main.jsx`。
2. 更新 Vite 多页面构建输入。
3. 实现四页静态内容和本地页码状态。
4. 读取当前快捷键用于展示；失败时使用示例值。
5. 完成/跳过调用 Rust 命令，保存失败时显示错误。

### 阶段 4：样式与设置入口

1. 完成独立 CSS、键帽、示例卡片、进度点和标题栏。
2. 支持小屏幕高度、文本溢出和 `prefers-reduced-motion`。
3. 设置页增加“重新打开新手向导”卡片和错误反馈。

### 阶段 5：验证与审查

1. 运行前端生产构建并确认 `dist/onboarding.html` 存在。
2. 检查向导页面的产物依赖，确认不加载主窗口 `App.css` 或通知 CSS。
3. 运行 Rust 格式、配置单元测试和可用的编译检查。
4. Windows 实机验证首次启动、跳过、重启、设置页重开、重复点击单实例和主窗口并行使用。
5. 检查目标 diff，确认未改动现有通知和主窗口导航；首次向导不增加快捷键或托盘门控。

## 验收标准

### 功能

- 新配置或缺少字段的配置在首次启动时主动显示向导，主窗口默认隐藏但仍可通过快捷键或托盘唤起；完成、跳过或关闭后确保主窗口显示。
- 点击“下一步 / 上一步”只切换四页本地内容，不触发主窗口行为。
- 点击“跳过”“开始使用”或关闭按钮后窗口关闭，重启应用不再自动出现。
- 应用设置中的“重新打开新手向导”可随时打开，并从第 1 页开始。
- 连续点击重新打开只存在一个 `onboarding-guide` 窗口。
- 设置页重开并关闭后，完成标志仍保持 `true`。

### 非阻塞与独立性

- 首次自动展示时主窗口默认隐藏但可由快捷键或非退出托盘入口唤起；设置页重开时主窗口仍可正常操作。
- 向导不注册全局键盘、窗口操作、搜索词、组件切换或完成检测监听器。
- 向导创建或调度失败时立即撤销门控并显示主窗口；索引和通知初始化不受影响。
- 完成状态保存失败时不关闭窗口，并给出可重试的错误提示。

### CSS

- 主窗口打开、关闭向导前后布局和样式无变化。
- 向导页面不受 `App.css` 中 `*`、`html/body/#root` 规则和设置页全局样式影响。
- 生产构建中向导有独立 HTML 入口与样式资源。
- 100%、125%、150% 缩放和常见小屏幕工作区中，底部操作按钮可见且内容不越界。

## 对抗式风险审查

| 风险 | 可能问题 | 处理方式 |
| --- | --- | --- |
| 旧用户配置缺字段 | 所有旧用户升级后也会看到一次 | 本计划明确推荐该行为；若产品不接受，实施前改为新安装识别方案 |
| 静态导入向导到现有 `main.jsx` | CSS 与主/通知窗口互相污染 | 使用独立 `onboarding.html`，不修改现有入口 |
| 将完成状态混入 `save_setting_data` | 保存其他设置时误覆盖向导状态 | 使用独立窄读写函数 |
| 先关闭再保存 | 保存失败导致下次再次弹出且用户不知道原因 | 保存成功后才关闭；失败留在页面 |
| 每次启动预创建向导 | 已完成用户仍承担 Webview 内存和启动成本 | 仅未完成时创建，设置页按需创建 |
| 多次点击设置按钮 | 创建多个窗口或 label 冲突 | 固定 label，ensure 函数幂等复用 |
| 硬编码快捷键 | 用户修改后向导内容错误 | 读取 `get_app_settings`，只在失败时回退示例 |
| 首次向导与主窗口同时显示 | 启动时界面杂乱 | 主窗口默认隐藏，向导不置顶；用户需要时可用快捷键或托盘唤起 |
| 向导置顶遮挡被唤起的主窗口 | 用户误以为快捷键无效 | 使用普通非模态窗口，不置顶；保留任务栏入口供用户切换 |
| Tauri 窗口创建发生在启动关键路径 | 启动出现短暂停顿 | setup 返回后再调度；失败只记录，不等待用户也不阻断初始化 |

## 非目标

- 不记录用户是否真的按过快捷键、打开过组件或完成过示例。
- 不做遥测、埋点、成就系统、强制教学或操作遮罩。
- 不从向导控制主窗口页面、搜索词、组件选择或窗口尺寸；首次流程只控制主窗口初始显示状态，不限制后续快捷键、托盘或主窗口使用。
- 不修改现有通知窗口架构或顺带修复通知 CSS 的既有全局入口问题。
- 不新增依赖库；使用现有 React、Tauri API 和普通 CSS。
- 不在本期实现多语言、远程内容、版本更新介绍或逐版本重复展示。
