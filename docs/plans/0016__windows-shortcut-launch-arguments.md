# Windows 快捷方式启动参数与索引边界

日期：2026-10-08
当前步骤：按 2026-10-12 确认的简化方案实施，已拆分目标字段和展示字段；应用内重建与启动待实机核验

## 最新确认的实施范围（2026-10-12）

下述原始计划中的工作目录字段、持久化 launch_key、表重建和启动 API 重构暂不实施，以本节及 `docs/应用索引扫描过滤流程.md` 为当前规则。

- 使用 `title`、`path`、`target_path`、`desc`、`arguments`：`title` 展示及辅助关联；`path` 启动原始入口；新增 `target_path` 记录目标；`desc` 只负责展示；`arguments` 原样保存。AppsFolder 和开始菜单 `desc` 留空，桌面、配置目录及手动应用显示普通目标路径。
- 去重使用规范化 `target_path` 与已知 `arguments`，不按标题去重，不考虑工作目录。参数或目标未知时按 `path` 保守保留。
- AppsFolder 读取 `System.Link.Arguments`，缺失时关联开始菜单及桌面 `.lnk`。只有同名同目标且所有候选参数一致、已知时关联成功。
- 快捷方式通过 Windows `IShellLinkW` 读取元数据，保留没有普通目标的系统入口，拒绝损坏文件。
- 统一所有来源的键编码，包括空参数；手动应用优先，其次 AppsFolder，并保留 AppsFolder 的启动入口和图标。
- `arguments`、`target_path` 数据库字段和迁移已完成；旧 `desc` 中的目标先迁入 `target_path`；原始 `.lnk` 保存在 `path`，各入口路径不同，因此本轮保持 `UNIQUE(path)`，跨来源去重在扫描阶段完成。
- `.lnk` 继续交给 Windows 打开，不额外附加参数；便携与可信入口沿用现有分级过滤，不新增扫描目录。
- 可信 `.lnk` 也必须通过目标类型过滤和小入口标题过滤；文档、网页、帮助、安装器和更新入口不进入应用索引。目标为 `.ico` 的快捷方式默认排除，但 MSI 广告式快捷方式及可靠恢复工作目录目标的特殊快捷方式保留，细则以当前流程文档为准。

## 目标与问题

将应用启动参数作为独立属性贯穿扫描、入库、搜索和启动。命令提示符、Node.js command prompt、Install Additional Tools for Node.js 即使共用 cmd.exe，也应保留各自的启动语义。

当前快捷方式解析依赖 working_dir 与 link_info.local_base_path 同时存在，丢弃 arguments，并按目标路径去重。控制面板、运行等 Shell 快捷方式不能保证存在普通 exe 目标。启动链路还会按进程名称判断是否只激活已有窗口，可能吞掉带参数的新启动请求。

## 设计决策

参数新增为原始字符串 `arguments`，保留引号、大小写和内部空白，不按空格拆分。工作目录新增为独立字段 `working_dir`。快捷方式原路径新增为 `shortcut_path`，明确区分启动入口与实际目标。

快捷方式默认交给 Windows Shell 启动原始 .lnk，保证参数、工作目录、特殊 Shell 目标及其他快捷方式属性由系统解释。arguments 仍保存用于诊断和启动身份计算；启动 .lnk 时不得再次附加解析出的参数，否则会重复传参。

普通 exe 使用目标路径与 arguments 启动；没有普通目标的快捷方式使用 .lnk 路径作为身份后备。系统特殊入口使用小范围、可测试的名称或系统标识放行，不扩展为品牌、目录或模糊关键词白名单。

## 扫描边界

| 来源 | 范围 | 收录边界 |
| --- | --- | --- |
| AppsFolder | 现有 Shell 应用目录 | 保留有效 Shell 启动入口；提取可用目标、参数，不要求存在 exe |
| 开始菜单 | 当前用户及公共 Programs，递归 | 收录 .lnk、现有直接 exe/rdp；不扩展到任意文档或 .url |
| 桌面 | 当前用户及公共桌面，不递归 | 收录 .lnk、exe、rdp；不收录 .url 和普通文件 |
| 配置目录 | 现有便携扫描范围 | 维持只收录 exe 的规则，不顺带扩大快捷方式扫描范围 |
| 手动应用 | 用户明确添加的记录 | 保留既有优先级和重建保护 |

快捷方式目标解析改为尽力提取：优先 Windows Shell Link API，环境变量目标按 Windows 规则展开，解析不要求工作目录存在。不通过执行快捷方式探测目标。不能解析为普通文件路径时，保留存在且有效的 .lnk；损坏快捷方式记录失败原因，不伪造 exe 目标。

不新增全盘、Windows 或 Program Files 扫描。目录排除继续遵守现有来源范围，注册目录抑制仅作用于便携 exe。

## 过滤边界

- 快捷方式以入口类型 .lnk 校验，不以解析目标必须是 exe/rdp 作为硬门槛；允许 Shell namespace、系统入口或没有普通目标的快捷方式。
- 缺少 working_dir、缺少普通目标、环境变量尚待展开、图标提取失败或图标与 no_icon 样本相似，不删除可信用户入口。
- AppsFolder、开始菜单、桌面快捷方式仍需过滤明显的设置、配置、卸载、更新、帮助文档和网页小入口；可信来源只意味着过滤规则应以用户可见标题为主，不能因此完全放宽。
- 对 Windows 自带的特殊用户入口使用明确放行名单，例如“命令提示符”“Windows PowerShell”“运行”“控制面板”“文件资源管理器”“任务管理器”等。放行名单只作用于明确的系统入口，不把所有名为“设置”或“配置”的快捷方式放行。
- 第三方应用的“设置”“配置”“选项”“卸载”“帮助”“文档”“网站”“更新”等快捷方式继续按标题和入口类型过滤；应用主入口即使目标文件名包含 launcher，也不能仅凭目标文件名删除。
- 便携裸 exe 保留现有严格辅助程序与目录抑制规则；no_icon 相似度过滤限定于该来源，不传播到可信入口。
- 启动参数不参与辅助程序关键词过滤，不能因参数中出现 update、helper 等词就删除入口。
- 单条解析或图标失败不终止整轮扫描；每次跳过记录来源、入口、目标和具体原因。参数诊断日志仅开发/显式诊断时启用，避免日常记录可能包含敏感内容的参数。

## 去重与数据库边界

新增 `arguments`、`working_dir`、`shortcut_path` 和持久化 `launch_key`。旧记录迁移为空字符串；历史参数无法恢复，自动记录通过重建补齐，手动记录保留。

启动身份使用结构化组合，避免简单字符串拼接碰撞：

1. 普通目标：规范化目标路径 + 原始参数 + 规范化工作目录。
2. Shell 入口：稳定 Shell 标识 + 参数 + 工作目录。
3. 无法可靠提取目标的快捷方式：规范化 .lnk 路径。

目标及工作目录按 Windows 路径规则比较；参数保持大小写、引号和空白，不做语义猜测。工作目录为空与显式目录保守视为不同。无法可靠解析的 Shell 项保持独立，不按名称合并。

同目标、不同参数必须共存；同目标同参数但不同工作目录也保留。完全相同身份按“手动 → AppsFolder → 开始菜单 → 桌面 → 便携”优先级合并。

必须调整当前 `UNIQUE(path)` 与所有按路径查重/更新的 SQL，不能只修改扫描器 HashSet。应用写入、手动 upsert、查询映射、md5 生成均使用明确启动身份；文件索引的路径唯一约束保持不变。旧 schema 通过事务重建应用表及索引，保留手动记录和 id，迁移失败回滚。

若 AppsFolder 未提供可靠参数，则不得仅凭实际 exe 路径抑制带参数快捷方式；Shell 标识与具体启动描述只有在明确等价时合并。

## 启动边界

| 入口 | 执行方式 | 参数与工作目录 |
| --- | --- | --- |
| 原始 .lnk | Windows ShellExecuteExW 打开 .lnk | 由快捷方式自身处理，不重复传入 arguments |
| 普通 exe | ShellExecuteExW，目标与参数独立传入 | 原始 arguments；有 working_dir 则使用，否则保持既有默认目录策略 |
| shell:AppsFolder | Windows Shell 激活 | 保留 Shell 身份，不转换成 exe，不额外附加不受支持的参数 |
| rdp | Windows 文件关联 | 保留既有行为，不拼接命令行 |

取消通过 `cmd /c start` 包装普通应用的路径，不拼接 shell 命令。用户参数中的 `&`、`|` 等不会被宿主额外解释；若目标本身是 cmd.exe，则由该目标解释其明确传入的参数。

带参数入口、.lnk 和 Shell 入口每次交给系统启动，不因同名进程存在而只激活窗口。仅普通无参数 exe 可以保留既有激活策略。这样 Node.js 命令提示符不会因 cmd 已运行而丢失初始化命令。

`open_app` 返回可识别错误，前端显示启动失败，避免 expect/panic。macOS 保持既有启动行为，新字段提供兼容默认值。

“打开所在目录”使用已解析实际目标；没有普通目标时定位原始 .lnk。图标优先读取快捷方式自身，再尝试目标及默认图标，不依赖目标解析成功。

## 验收

- 命令提示符与两个 Node.js 快捷方式可分别搜索，Node.js 环境初始化及安装工具入口保留原始行为；安装工具只核对元数据，不实际执行安装。
- 控制面板、运行、文件资源管理器在没有 local_base_path 或 working_dir 时仍能入库，并通过 .lnk 启动。
- 有环境变量、空格、引号和中文的目标/参数正确保留；缺失工作目录不会删除入口。
- cmd 已运行时，Node.js 命令提示符仍发起独立启动。
- 相同目标不同参数/工作目录共存，完全相同启动身份合并；参数大小写不被误归一化。
- 旧数据库迁移、自定义记录保护、重建事务回滚及应用查询映射具有聚焦 Rust 测试。
- `cargo fmt`、相关 `cargo test`、`cargo check`、`pnpm build`、`git diff --check`；Windows 实机手工核验上述入口、图标及打开所在目录。

## 非目标

本轮不增加参数编辑器、管理员启动开关、任意脚本扫描或通用命令执行功能。不实现对任意命令行语义的解析与等价判断，不自动执行安装/卸载入口验证结果。
