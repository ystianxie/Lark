# 文本结果快速粘贴机制

## 1. 目标

当用户在 Lark 中选择 `result` 类型的文本结果后，宿主应将完整文本一次性粘贴到唤醒 Lark 前光标所在的输入控件中。

该链路有两个核心要求：

1. 保持原有目标位置不变，即仍由操作系统把焦点还给唤醒前的窗口和输入控件。
2. 文本量增大时，耗时不应随字符数呈明显的逐字符增长，也不应因模拟键入过慢而被截断。

## 2. 设计结论

文本结果采用“写入系统剪贴板，再模拟一次粘贴快捷键”的方式注入，不再使用 `enigo.text(...)` 逐字符模拟键盘输入。

原因如下：

- 逐字符输入需要为每个字符生成键盘事件，性能与文本长度直接相关。
- 目标应用处理键盘事件的速度不稳定，大段文本可能卡顿、丢字符或被截断。
- 剪贴板粘贴由目标控件一次接收完整数据，更接近用户手动按 `Ctrl+V` 或 `Cmd+V` 的行为。
- 继续使用系统快捷键而不是直接操作目标控件，可以保留“自动输入到唤醒前光标位置”的通用能力，无需针对浏览器、编辑器或聊天软件分别适配。

## 3. 调用链

```text
用户选中 result 并按 Enter
        │
        ▼
App.jsx 隐藏 Lark 窗口
        │
        ▼
操作系统将焦点还给唤醒前的窗口/输入控件
        │
        ▼
clipboard_control(control="write", paste=true, dataType="text")
        │
        ├─ ClipboardOperator::set_text(text)
        │      将完整结果写入系统剪贴板
        │
        └─ ClipboardOperator::paste_text()
               等待 50ms 让焦点恢复
               Windows/Linux: Ctrl+V
               macOS: Cmd+V
```

相关入口：

- 前端结果处理：`src/App.jsx` 的 `currentComponent.type === "result"` 分支。
- Tauri 命令：`src-tauri/src/api/shell.rs` 的 `clipboard_control`。
- 系统粘贴：`src-tauri/src/api/clipboard.rs` 的 `ClipboardOperator::paste_text`。

## 4. 行为约束

### 4.1 焦点不变量

前端必须先 `await appWindow.hide()`，再调用 `clipboard_control`。Lark 隐藏后，操作系统负责恢复此前窗口的焦点，因此粘贴目标仍是唤醒 Lark 前光标所在的输入控件。

底层在发送粘贴快捷键前等待 50ms。这个等待不是为了传输文本，而是避免 Lark 刚隐藏、焦点尚未完成切换时过早发送快捷键。它是一个兼容性缓冲值，不代表操作系统提供了“焦点已恢复”的确定性通知。

### 4.2 剪贴板行为

粘贴完成后，文本结果会保留在系统剪贴板中。这与修改前的行为一致，因为旧实现同样会先调用 `set_text`。

剪贴板监听器会同时轮询系统剪贴板并写入历史库。为避免本次“写入剪贴板 → 粘贴”被当成用户新复制，`clipboard_control` 在文本粘贴路径登记本次文本，监听器在 3 秒内遇到完全相同的文本时消费该标记并跳过入库，同时推进去重摘要。这个机制是一次性回环抑制，不是按时间简单丢弃所有剪贴板变化，因此用户稍后主动复制相同文本仍可正常记录。

### 4.3 错误传播

写入剪贴板或模拟快捷键失败时，Rust 错误会转换为字符串并返回给前端，不再静默忽略。

按键发送遵循以下顺序：

1. 按下 Ctrl 或 Cmd。
2. 单击 V。
3. 释放 Ctrl 或 Cmd。
4. 返回按 V 或释放修饰键时产生的错误。

即使发送 V 失败，也会尝试释放修饰键，以降低 Ctrl/Cmd 保持按下状态的风险。

### 4.4 日志安全

`clipboard_control` 只记录前 100 个 Unicode 字符作为预览，并通过 `text.chars().take(100)` 截取。禁止使用 `&text[..N]` 按 UTF-8 字节位置切片，否则中文、Emoji 等多字节字符可能在边界处触发 panic。

## 5. 方案比较

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| `enigo.text(...)` 逐字输入 | 不依赖剪贴板粘贴能力 | 长文本慢；事件量大；目标应用可能丢字符或截断 | 不用于文本结果注入 |
| 剪贴板 + Ctrl/Cmd+V | 快；文本长度对按键事件数量影响很小；兼容多数输入控件 | 会覆盖用户剪贴板；依赖焦点恢复和目标应用允许粘贴 | 当前推荐方案 |
| Windows UI Automation / macOS Accessibility 直接写控件 | 可针对控件精确赋值 | 平台差异大；权限要求高；并非所有应用暴露可写控件 | 仅在未来有强需求时考虑 |

当前方案是最小且通用的改动。恢复用户原剪贴板看似更友好，但恢复时机难以可靠判断：目标应用可能尚未读取剪贴板，过早恢复会粘贴出旧内容。因此当前不自动恢复剪贴板。

## 6. 已知边界与风险

- 固定等待 50ms 是经验性缓冲；在高负载设备或焦点切换异常的窗口管理环境中仍可能过短。
- Windows 的完整性级别限制可能阻止普通权限进程向管理员权限窗口发送模拟按键。
- 密码框、远程桌面、虚拟机、游戏或带安全策略的应用可能禁止模拟粘贴。
- 目标输入控件自身可能设置最大长度；这种截断不属于 Lark 的文本传输截断。
- 当前行为会覆盖系统剪贴板，并可能被 Lark 的剪贴板历史监听器记录。
- 文本结果粘贴的内部写入在 3 秒窗口内不会重复写入剪贴板历史；如果系统焦点切换或剪贴板读取延迟超过该窗口，仍需依赖实际测试确认。
- Linux 使用 Ctrl+V 分支，但项目当前主要声明 Windows/macOS 支持；不同桌面环境仍需单独验证。

如果真实设备上持续出现焦点竞争，优先考虑捕获并恢复目标窗口句柄，或增加有限次数的焦点确认机制；不应重新退回逐字符输入。

## 7. 验收清单

至少在下列场景进行手工验收：

- 纯英文、中文、Emoji 和多行文本均能完整粘贴。
- 1 字符、空白字符以及 10KB 以上长文本行为正确。
- 唤醒前光标位于文本中间时，结果插入当前位置，而不是固定追加到末尾。
- 浏览器输入框、记事本、代码编辑器和常用聊天输入框均能接收文本。
- 连续多次唤醒并选择结果时，粘贴目标不会落到 Lark 自己的输入框。
- 粘贴失败后 Ctrl/Cmd 不会保持按下状态。
- 包含超过 100 个中文字符或 Emoji 的文本不会使日志预览触发 panic。
- 在管理员权限窗口中验证并记录权限不一致时的预期失败行为。

## 8. 关键假设

- 用户选择文本结果时，覆盖系统剪贴板是可接受的，并与原有产品行为一致。
- Lark 窗口隐藏后，操作系统通常会把焦点还给此前窗口。
- 目标控件支持标准的 Ctrl+V 或 Cmd+V 粘贴快捷键。
- 当前优先解决长文本性能与完整性，不在本次改动中引入跨平台辅助功能 API。

## 9. 窗口唤醒与状态恢复

窗口通过 Alt+Space 从隐藏状态唤醒时，Rust 快捷键处理器不再直接调用 `show()`，而是先发送 `window-show-request` 事件。前端收到事件后按模式分流：

```text
window-show-request
        │
        ├─ componentInfo.type === "panel"
        │      保留 panel、插件状态和当前窗口尺寸
        │      show → setFocus → 恢复 WebView/输入焦点
        │
        └─ 其他模式
               flushSync 提交 initStatus()
               等待 compact 尺寸设置完成
               show → setFocus → 恢复输入焦点
```

普通模式使用 `flushSync` 是因为 React 状态更新默认可能延迟到当前事件处理结束后提交；如果先显示窗口再等待 React 重绘，用户会看到旧结果、旧输入内容或旧窗口高度短暂闪现。`initStatus()` 同时递增 `searchRequestId`，使隐藏前尚未完成的异步搜索返回后自动失效，避免旧结果重新写回。

panel 模式不能调用 `initStatus()` 或 `modifyWindowSize("compact")`。panel 的插件界面和 expanded 尺寸属于正在进行的交互状态，唤醒只应恢复可见性和焦点。

## 10. 激活后的隐藏策略

窗口隐藏不再依赖失焦事件这一种副作用。激活会结束当前 Lark 交互的条目，在执行外部动作后显式调用 `appWindow.hide()`，包括：

- `result`：先隐藏窗口，再写入剪贴板并模拟粘贴。
- `app`：打开应用或资源管理器后隐藏。
- `url` / `search`：打开浏览器后隐藏。
- `file`：打开文件或资源管理器后隐藏。
- `action`：动作无结果时隐藏；有结果时保留结果列表供用户继续选择。

失焦监听仍作为普通模式的兜底，但必须读取 `componentInfoRef.current`，不能使用 effect 创建时捕获的旧 `componentInfo`。否则监听器会把 panel 错判成普通模式，在 panel 失焦时执行隐藏和 compact 重置。

## 11. 相关实现位置与回归检查

- 唤醒事件发送：`src-tauri/src/main.rs` 的全局快捷键处理；`src-tauri/src/utils/window.rs` 的 `set_window_show` 命令。
- 唤醒前重置与 panel 分流：`src/App.jsx` 的 `window-show-request` 监听器。
- 状态重置及异步搜索失效：`src/App.jsx` 的 `initStatus()`。
- 激活后的窗口隐藏：`src/App.jsx` 的 `confirmComponentSelected()`。

回归检查至少覆盖：

1. 普通搜索结果唤醒后显示为 compact 空状态，且看不到旧内容或尺寸闪现。
2. panel 唤醒后保留插件页面、插件内部状态和 expanded 尺寸。
3. 激活 app、url、search、file 及 result 后窗口均隐藏。
4. 隐藏前发起的慢搜索在重新唤醒后不会覆盖新的空状态。
