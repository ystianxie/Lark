# 文件搜索分层查询优化 Chronicle

日期：2026-09-17
计划：`docs/plans/0007__file-search-layered-query.md`
状态：完成

## 背景

现有文件搜索对 `title` 和 `path` 执行带前置通配符的 `LIKE`，并对全部匹配结果排序。单字符关键词会命中大量记录，造成明显延迟；30ms 防抖只能减少部分请求，不能降低单次 SQL 成本。

## 决策

采用分层查询：单字符只走文件名前缀；多字符仅在上一层不足 30 条时继续更宽泛的匹配。普通文件搜索防抖设为 80ms。数据库初始化与查询连接创建解耦。

## 实施结果

- 单字符只执行精确标题和标题前缀查询。
- 两个及以上字符按标题包含、路径包含逐层补足 30 条。
- 新增 `title COLLATE NOCASE` 索引，使精确与前缀层可使用索引。
- 使用 `OnceLock` 保证索引数据库 schema 初始化每个进程只执行一次。
- 普通输入防抖从 30ms 调整为 80ms。
- 新增单字符、分层回退和 LIKE 通配符转义测试。

## Explain diff

核心概念是“逐层扩大召回范围”：先运行便宜且相关性高的查询，只有结果不足时才运行更昂贵的子串查询。单字符不进入任意子串层，从根源上避开最宽泛的扫描。

## Review

- 已检查分页：各层最多收集 `offset + 30` 条，再统一跳过 offset，避免分页破坏层级优先级。
- 已检查重复：每一层 SQL 显式排除前面层级的标题范围，路径层排除所有标题命中。
- 已检查用户输入 `%`、`_` 和反斜杠：在 LIKE 前进行转义。
- 已限制通用表参数：分层实现只接受 `file_index`，避免未来误用于其他表。
- 已知限制：两个及以上字符且前缀/标题结果不足时，包含层仍可能全表扫描；这是本阶段保留任意子串语义的成本。
