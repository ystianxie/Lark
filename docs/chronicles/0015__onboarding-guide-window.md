# 四页新手向导独立窗口 Chronicle

日期：2026-09-30  
计划：`docs/plans/0015__onboarding-guide-window.md`  
状态：已调整首次向导期间主窗口可见性，等待 Tauri 实机复测

## 背景

用户希望新增一个不监听真实操作的四页向导，通过示例说明快捷键和主要功能，并用持久化初始化变量控制首次弹出。向导必须独立于主窗口运行，设置页可重新打开，样式不能污染其他窗口。

## 最终决策

- 采用 Rust 管理的独立 Tauri Webview 单实例窗口，不使用主窗口 Modal。
- 采用独立 `onboarding.html` 和独立 React/CSS 入口，避免现有 `App.css`、通知 CSS 与设置页全局样式交叉加载。
- 使用 `onboarding_completed` 持久化字段；跳过、开始使用和向导内关闭均在保存成功后关闭窗口。
- 窗口设置 `closable(false)`，避免 Alt+F4 或任务栏关闭绕过持久化边界；用户仍可使用向导内关闭、跳过和完成按钮。
- 设置页重新打开只打开窗口，不重置完成状态。
- 四页仅提供说明和静态示例，不监听或验证主窗口操作。

## 实施内容

### 配置与后端

- `BaseConfig` 新增带 `#[serde(default)]` 的 `onboarding_completed: bool`，Windows/macOS 默认均为 `false`。
- 新增窄写入函数 `save_onboarding_completed` 和旧配置缺字段兼容测试。
- 新增固定 label `onboarding-guide` 的幂等窗口创建函数，以及 `open_onboarding`、`complete_onboarding` 命令。
- 首次启动仅在完成标志为 `false` 时异步调度窗口创建；失败只写日志，不中断主应用初始化。
- 自动弹出不主动聚焦；设置页显式重开时显示、居中并聚焦已有窗口。

### 独立前端

- 新增 `onboarding.html`、`src/onboarding/main.jsx`、`OnboardingGuide.jsx` 与专用 CSS。
- Vite 改为显式多页面输入，保留主入口并增加 onboarding 入口。
- 四页依次为：呼出/输入/执行、文件搜索与结果快捷操作、剪贴板与文件选择框跳转、内置组件与组件库。
- 向导只读取一次当前快捷键；读取失败使用默认展示值，不影响翻页或关闭。
- 页面只有 React 按钮事件，不注册键盘、鼠标、全局快捷键、窗口事件或主窗口状态监听。

### 设置入口

- 应用设置新增“新手向导”卡片和“重新打开”按钮。
- 打开失败复用既有 `settingNotice` 错误反馈；该操作不修改完成标志。

## 首次使用窗口语义调整（2026-09-30）

- `tauri.conf.json` 将主窗口改为启动时默认隐藏，避免首次引导时主窗口先闪现。
- `onboarding_completed == false` 时主窗口默认隐藏并聚焦向导；用户仍可通过快捷键或托盘唤醒主窗口，完成、跳过或关闭向导且状态保存成功后，确保主窗口显示并聚焦。
- 首次向导有效期间，不屏蔽唤醒/剪贴板/文件跳转快捷键以及非退出托盘入口；向导不置顶，用户可以边看边试；索引、插件、通知等后台初始化不暂停。
- 设置页“重新打开”不启用首次门控，因此不会隐藏主窗口，也不会影响正常快捷键和托盘操作。
- 向导创建或主线程调度失败时会撤销门控并回退显示主窗口，避免用户进入不可恢复的隐藏状态。

## 运行时回归修复（2026-09-30）

### 实机现象

- 首次自动弹出正常。
- 从应用设置重新打开时，向导出现白屏，主窗口响应异常，已注册快捷键也无法再唤出主窗口。

### 根因与修复

- 设置页的同步 `open_onboarding` IPC 原先直接执行 WebView 创建；与首次启动的异步事件循环路径不同。创建第二个 WebView 时，当前 invoke 未返回，窗口初始化和主事件循环可能互相等待，因此白屏、主窗口阻塞和快捷键失效是同一个事件循环阻塞的连锁表现。
- `open_onboarding` 现先切到 Tauri 异步运行时，再通过 `run_on_main_thread` 把创建任务投递回主事件循环，确保同步 IPC 先返回；不能直接在同步命令里调用 `run_on_main_thread`，因为调用者已在主线程时闭包仍会立即执行。
- 新窗口改用 `WebviewWindowBuilder::center()` 在构建参数阶段居中，删除 `build()` 后立即调用 `window.center()` 的同步窗口查询，遵循通知窗口已有的“新 WebView 进入消息循环前不读取窗口状态”原则。
- 该次白屏修复只涉及向导窗口调度与定位；随后按首次使用语义调整了主窗口初始可见性和向导窗口置顶策略，快捷键/托盘不再被首次向导门控，向导独立 CSS 仍未改动。
