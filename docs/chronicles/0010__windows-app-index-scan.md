# Windows 应用索引扫描优化 Chronicle

日期：2026-09-20
计划：`docs/plans/0010__windows-app-index-scan.md`
状态：完成

## 背景

现有 Windows 应用索引主要递归读取开始菜单、桌面和用户配置目录。该方式依赖快捷方式解析，无法稳定覆盖计算器、记事本和 Microsoft Store/UWP 应用，同时容易把目录中的更新器、卸载器和辅助进程当作应用。

## 决策

复用已有 `shell:AppsFolder` 枚举作为 Windows 注册应用来源，便携目录仅作为显式补充。不同来源统一转换为应用索引，按规范化启动目标去重，注册应用优先于便携扫描，自定义数据库记录保持最高优先级。

## 实施结果

- Windows 自动应用来源改为 AppsFolder 注册应用，保留用户配置的便携 `.exe` 目录补充。
- AppsFolder 条目保留 Shell 启动标识和可选真实可执行路径；传统注册应用用真实路径与便携结果去重。
- 自动发现记录在一个数据库事务中替换，自定义应用记录保持优先且不被清理。
- Store/UWP 启动目标通过 ShellExecute 打开；图标读取失败只回退为空图标，不删除应用。
- 属性读取、空名称、空启动目标和无效图标路径按单条记录隔离。

## Explain diff

核心变化是把“文件存在”与“用户可启动应用”分开：AppsFolder 是 Windows 的用户可见应用目录，文件系统扫描只负责显式配置的便携应用。优先级通过写入顺序、规范化启动身份和数据库自定义记录保护共同实现。
