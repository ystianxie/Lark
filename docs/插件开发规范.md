# Lark 插件开发规范

## 目录

```text
plugins/<plugin-id>/
├─ manifest.json
├─ dist/main.js
├─ dist/style.css
├─ python/main.py
└─ assets/
```

## Manifest

`manifest.json` 是唯一正式入口。必填字段：`id`（小写字母、数字、短横线）、`name`、`version`（SemVer）、`apiVersion`、`description`、`entry`、`workflows`。资源路径相对插件根目录。

```json
{
  "id": "json-handle",
  "name": "JSON 格式化",
  "version": "1.0.0",
  "apiVersion": 1,
  "description": "格式化 JSON",
  "entry": {"type": "js", "path": "dist/main.js"},
  "workflows": [{"id":"format-json","keywords":["json"],"type":"action","handler":"format"}],
  "permissions": ["clipboard.read", "clipboard.write"]
}
```

workflow 类型为 `action`、`panel`、`url` 或 `python`；必须有唯一 `id` 和 `keywords`。权限按最小需要声明。`panel` 表示由宿主展开窗口并挂载插件界面的页面。

可选的 `config` 用于声明插件需要用户填写的配置项（API Key、接口地址等），由宿主渲染表单，插件无需自己写界面，详见「插件配置」。

宿主内部条目类型统一为 `app`、`file`、`url`、`result`、`action`、`input-panel`、`panel`。`subpage`、`view`、`component` 和 `search` 不再作为新协议类型使用；`search` 统一按 `url` 处理。

窗口模式使用 `compact`（单行/少量结果）、`result-list`（多行搜索结果）和 `expanded`（panel 页面），不再使用含义不明确的 `small`、`big`。

## 组件库与启用状态

宿主通过 `load_plugins` 自动发现插件，无需额外维护注册列表。搜索“组件库”打开管理页面，可以查看插件名称、版本、描述和 workflow 关键词，并开启或关闭整个插件；声明了 `config` 的插件还会显示「配置」按钮。新增、移除或修改 manifest 后点击“刷新”更新列表；修改已运行的 JS 入口后需重启宿主。

发现顺序为用户插件目录、开发模式下仓库的 `plugins/`、应用资源目录的 `plugins/`，相同 `id` 优先使用先发现的插件。名称、版本、描述直接使用 manifest 的 `name`、`version`、`description`；图标优先使用可选的 manifest `icon`，否则使用首个带图标的 workflow，路径相对插件根目录。

新插件默认开启。用户开关复用宿主 WebView 的 `localStorage.pluginStatus`，以稳定的 manifest `id` 为键，例如 `{"timestamp":{"enable":false}}`，重启后保留。开关是用户偏好，无需向 manifest 添加 `enabled` 字段，也不修改插件文件或 Rust 配置。禁用会阻止宿主搜索、选择该插件的所有 workflow，但不会卸载插件或终止已经启动的外部任务；此开关不是权限隔离机制。

组件库始终保留已关闭插件，便于重新开启。JSON 解析失败或缺少基本注册字段的记录显示错误且不可开启，不参与搜索。内置文件搜索、组件库、应用设置等宿主功能不属于此插件列表。

## 插件配置

插件可在 manifest 里用可选的 `config` 声明自己需要用户填写的配置项，由宿主渲染表单：

```json
"config": {
  "schemaVersion": 1,
  "fields": [
    {"key": "api_key", "label": "API Key", "type": "password", "required": true,
     "description": "在服务商控制台获取"},
    {"key": "base_url", "label": "接口地址", "type": "text", "default": "https://api.deepseek.com/v1"},
    {"key": "model", "label": "模型", "type": "select", "options": ["deepseek-chat"], "default": "deepseek-chat"}
  ]
}
```

- `fields` 最多 24 项；`key` 必须是蛇形命名（小写字母开头，后跟小写字母、数字或下划线，最多 32 字符），在同一插件内唯一；`label` 必填。
- `key` 的规则与插件 ID 不同，刻意不复用：插件 ID 会成为目录名，需要路径安全；配置项 `key` 只是 JSON 对象键，因此允许下划线。蛇形命名让 JS 侧可以点号访问（`config.api_key`），Python 侧读字典本来就用 `config["api_key"]` 或 `config.get("api_key")`。
- `type` 支持 `text`、`password`、`number`、`boolean`、`select`、`textarea`。`select` 必须提供非空 `options`（字符串数组或 `{value,label}` 数组）；`default` 的类型必须与 `type` 一致。
- `required: true` 的项未填写时，宿主在搜索中选中该插件会先进入配置页，而不是执行插件。

配置值由宿主保存（按插件 `id` 存在宿主配置文件里），不会写回插件目录：

- 声明了配置项的插件在组件库卡片上出现「配置」按钮，进入由 `fields` 生成的表单；保存后立即可用，无需重启。
- 插件用 `await context.api.getConfig()` 读取，返回当前配置对象；未填写的项不在返回值中，请用声明的 `default` 兜底。
- 需要自绘配置界面的插件可用 `await context.api.setConfig(values)` 写回；宿主只保留 `fields` 中声明过的 `key`。
- Python 入口不需要自己取配置：向导生成的 JS 桥梁会先调用 `getConfig()`，再把结果放进 `runPython` 的 `args.config`，因此生成的 handler 签名是 `def handler(text, file, config)`，`config` 是已保存配置的字典（未配置时为空字典，不会是 `None`）。
- 单个插件的配置序列化上限为 64 KB。插件被删除或卸载后配置保留，可在配置页用「清除配置」显式删除。

密钥类字段请使用 `type: "password"`，表单会掩码显示。需要明确的是：配置当前以明文保存在宿主配置文件中，该类型只是为将来升级到加密存储留出余地；插件运行在宿主同一 WebView 上下文内，这层存储不构成插件之间的隔离。

## 新增插件向导

在组件库点击“新增插件”，填写插件 ID、名称、描述，再添加一个或多个功能入口。向导支持 `action`、`url`、`python`，不生成 `panel`；版本为 `1.0.0`，API 版本为 `1`。每个入口填写唯一 ID、名称、逗号分隔的关键词。ID 使用小写字母、数字和单个短横线，最多 64 字符，不能使用 Windows 保留名称。插件 ID 不可与已发现的插件重复。

- `url`：填写固定完整网址，允许 http、https、mailto、chrome-extension、moz-extension，不支持脚本地址或输入替换。
- `action`：填写 JS 异步函数体，例如 `return text.toUpperCase();`。可使用 `text`、`file`、`context`，可使用 `await`。所需宿主 API 权限在表单中勾选，默认无权限。权限最终取所有入口的并集，属于插件级权限。
- `python`：填写 Python 函数体，例如 `return text.upper()`，可使用 `text`、`file`、`config`。向导自动生成 JS 桥梁、Python 分发和 JSON 响应包装，并声明 `python.execute`；无需自己处理 stdin/stdout。业务代码中的 `print` 重定向到 stderr。
- 配置项变量名同时就是 `config` 字典的键。因为是蛇形命名，`config.api_key`（JS）与 `config["api_key"]`（Python）都能直接取用。

向导里还可以声明配置项（变量名、显示名称、类型、默认值、说明、是否必填；`select` 类型填写逗号分隔的选项）。填写后生成的 `manifest.json` 会带上 `config.fields`，`scaffold.json` 保存同一份声明；不填则不会生成 `config` 字段。校验规则与「插件配置」一节一致。

业务函数可以返回字符串、数字、`{title, data, desc}` 对象或它们的数组；`null` / `None`、空字符串、空数组表示无结果。数字 `0` 是有效结果。结果对象的结构化 `data` 会转成 JSON 文本。异常由宿主显示，结果选中后沿用宿主的文本粘贴行为。

action / python 在选择入口后进入宿主输入模式，先用空输入执行一次，之后非空文本变化 200ms 后实时执行。向导为 workflow 设置 `interactive: true`、`debounceMs: 200`；这些字段可选，现有插件无需迁移。单个入口串行执行，期间仅保留最新输入，过期结果不回填；清空输入或退出不会撤销已经产生的副作用。实时模式适合转换工具，不应用于需要确认的破坏性操作。

“预览生成文件”只生成文本，不运行代码。确认创建后，宿主将文件写入用户插件目录（以 `get_app_dir().plugins` 返回值为准），默认开启并刷新组件库。文件包括 `manifest.json`、`dist/main.js`、一个图标文件（`assets/icon.svg` 或 `assets/icon.<位图扩展名>`）、`README.md`、`scaffold.json` 及按需生成的 `python/main.py`。无需编译或安装 npm 依赖；代码语法和运行异常在执行入口时报告。

`scaffold.json` 的 `schemaVersion: 1` 保存创建配置，仅供开发参考，不是宿主入口；修改它不会自动重建其他文件。组件库可编辑向导创建的插件，但不提供依赖安装。创建接口 `create_plugin({pluginId, files})` 返回创建目录，限定固定文件名、校验 manifest、拒绝覆盖，最后发布 manifest，写入失败清理本次目录。文件创建成功但开启或刷新失败时可单独重试，不再写文件。

Python 使用「应用设置 → Python 环境」里配置的解释器（指向虚拟环境时选它下面的 `Scripts\python.exe` 即可，无需激活）；未配置时回落系统 `python.exe` / `python3`，默认超时 30 秒。向导不写死解释器路径、不创建虚拟环境。宿主通过 UTF-8 JSON 传参，并并行读取 stdout/stderr。该解释器同时用于插件的 `runPython` 和外部 Python 索引脚本；manifest 里不再有任何解释器配置项。

## JavaScript API

入口导出 `activate(context)`，返回 `execute(name, payload)`、可选 `mount(container, props)` 与 `unmount()`。插件不得直接调用 Tauri `invoke`、修改宿主 React 状态或操作宿主全局 DOM。

context 包含 `theme`、`input`、`ui`、`api`。`theme` 提供 CSS 变量（如 `--lark-color-bg`、`--lark-color-text`）；`input` 是调用时快照；`ui` 提供 `setTitle`、`setLoading`、`showResult`、`notify`、`close`；`api` 按权限提供 `openUrl`、`openFile`、`readClipboard`、`writeClipboard`、`runPython`，并提供不受权限限制的 `getConfig()` 与 `setConfig(values)`（见「插件配置」）。两者都是异步的，且每次都向宿主取值，因此在组件库改完配置后无需重启即可读到新值。

## Python

通过 `context.api.runPython(task, args)` 调用。宿主使用用户在「应用设置 → Python 环境」里配置的解释器（Windows 默认 `python.exe`，macOS/Linux 默认 `python3`），以 JSON 传递参数，不拼接 shell 命令。Python 输出单个 JSON 响应：`{"ok":true,"result":...}`；异常、超时、非零退出码均返回结构化错误。宿主不自动创建虚拟环境，也不安装依赖：插件需要第三方包时，请自行准备环境并在设置页指向它。

向导为 Python workflow 生成的 JS 桥梁会自行注入配置：先 `await context.api.getConfig()`，再以 `{text, file, config}` 作为 `args` 调用 `runPython`。对应的 `python/main.py` 里 handler 签名是 `def handler_i(text, file, config)`，分发层传入 `args.get("config") or {}`，因此业务代码可以直接使用 `config` 字典，宿主不会把配置塞进命令行或环境变量。手动安装的插件如果自己解析 `args`，同样可以读取 `config` 字段。

## 开发与发布

开发阶段可使用 Vite 直接加载源码并热更新；发布阶段由插件作者自行构建到 `dist`，宿主不编译插件，也不要求使用 Rollup。发布包必须包含 manifest 和 entry 指向的文件。

## 迁移与调试

向导补充说明：`action` 和 `python` 入口选中后先用空输入执行一次，随后对非空输入按 200ms 防抖实时执行；一个插件的多个 Python workflow 共用 `python/main.py`，由请求中的 `task` 与 workflow 的 `handler` 名称分发。创建页面支持拖拽或选择图标文件，未上传时生成随机风格 SVG。

图标的接受范围：SVG 允许 XML 声明、注释与 DOCTYPE 前缀（导出工具的常见产物），也允许 `url(#id)` 这类指向同一文件内渐变、滤镜或图案的引用；不允许 `script`、`foreignObject`、`iframe`、`object`、`embed`、事件属性（如 `onclick`）、指向 http/data/javascript 的 `href`/`src`、`@import`、`<!ENTITY`，以及指向外部资源的 `url()`。位图支持 PNG、JPEG、WebP 与 ICO，要求文件头与扩展名相符且不超过 256 KB。不满足时向导会指出具体原因，并沿用生成的默认图标。

图标只允许写入 `assets/icon.svg`、`assets/icon.png`、`assets/icon.jpg`、`assets/icon.webp` 或 `assets/icon.ico` 之一，manifest 的 `icon` 指向实际提供的那个。位图在传输时是 base64 文本，宿主落盘前解码为二进制。手动安装的插件不受此限制，manifest 的 `icon` 可以指向插件目录内的任意图片。

组件库的“编辑”功能只对向导创建且保留合法 `scaffold.json` 的用户插件开放。可编辑名称、描述、图标（SVG 或位图，可互相切换）、功能入口、关键词、类型、URL、业务代码、JS API 权限和配置项；保存时重新生成 `manifest.json`、`dist/main.js`、`README.md`、`scaffold.json` 以及按需生成的 `python/main.py` 和图标文件，切换图标格式时旧的图标文件会被删除。插件 ID、协议版本、版本号、固定入口路径和目录结构不可编辑。手动安装或缺少合法 `scaffold.json` 的插件需直接修改文件。

将 `info.json` 重命名为 `manifest.json`，`title` 改为 `name`，`workflow` 改为 `workflows`，`keyword` 改为 `keywords` 数组，并为每项补充 `id`、`type`。加载失败只影响当前插件；检查 Lark 日志中的插件 id 和错误信息。
