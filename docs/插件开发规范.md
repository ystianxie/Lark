# Lark 插件开发规范

## 目录

```text
plugins/<plugin-id>/
├─ manifest.json
├─ dist/main.js
├─ dist/style.css
├─ python/main.py
└─ assets/
```

## Manifest

`manifest.json` 是唯一正式入口。必填字段：`id`（小写字母、数字、短横线）、`name`、`version`（SemVer）、`apiVersion`、`description`、`entry`、`workflows`。资源路径相对插件根目录。

```json
{
  "id": "json-handle",
  "name": "JSON 格式化",
  "version": "1.0.0",
  "apiVersion": 1,
  "description": "格式化 JSON",
  "entry": {"type": "js", "path": "dist/main.js"},
  "workflows": [{"id":"format-json","keywords":["json"],"type":"action","handler":"format"}],
  "permissions": ["clipboard.read", "clipboard.write"]
}
```

workflow 类型为 `action`、`panel`、`url` 或 `python`；必须有唯一 `id` 和 `keywords`。权限按最小需要声明。`panel` 表示由宿主展开窗口并挂载插件界面的页面。

宿主内部条目类型统一为 `app`、`file`、`url`、`result`、`action`、`input-panel`、`panel`。`subpage`、`view`、`component` 和 `search` 不再作为新协议类型使用；`search` 统一按 `url` 处理。

窗口模式使用 `compact`（单行/少量结果）、`result-list`（多行搜索结果）和 `expanded`（panel 页面），不再使用含义不明确的 `small`、`big`。

## JavaScript API

入口导出 `activate(context)`，返回 `execute(name, payload)`、可选 `mount(container, props)` 与 `unmount()`。插件不得直接调用 Tauri `invoke`、修改宿主 React 状态或操作宿主全局 DOM。

context 包含 `theme`、`input`、`ui`、`api`。`theme` 提供 CSS 变量（如 `--lark-color-bg`、`--lark-color-text`）；`input` 是调用时快照；`ui` 提供 `setTitle`、`setLoading`、`showResult`、`notify`、`close`；`api` 按权限提供 `openUrl`、`openFile`、`readClipboard`、`writeClipboard`、`runPython`。

## Python

通过 `context.api.runPython(task, args)` 调用。宿主使用用户配置的 Python（Windows 默认 `python.exe`，macOS/Linux 默认 `python3`），以 JSON 传递参数，不拼接 shell 命令。Python 输出单个 JSON 响应：`{"ok":true,"result":...}`；异常、超时、非零退出码均返回结构化错误。第一版不自动创建虚拟环境。

## 开发与发布

开发阶段可使用 Vite 直接加载源码并热更新；发布阶段由插件作者自行构建到 `dist`，宿主不编译插件，也不要求使用 Rollup。发布包必须包含 manifest 和 entry 指向的文件。

## 迁移与调试

将 `info.json` 重命名为 `manifest.json`，`title` 改为 `name`，`workflow` 改为 `workflows`，`keyword` 改为 `keywords` 数组，并为每项补充 `id`、`type`。加载失败只影响当前插件；检查 Lark 日志中的插件 id 和错误信息。
