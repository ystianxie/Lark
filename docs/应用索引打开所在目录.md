# 应用索引：打开应用所在目录

## 功能概述

在应用索引搜索结果中触发“打开所在目录”后，后端通过 `open_explorer` 打开应用文件所在的目录，并尝试将对应的资源管理器窗口恢复到前台。

实现位置：

- `src-tauri/src/api/explorer.rs`
- 函数：`open_explorer`

## Windows 实现流程

1. 使用 Explorer 的选择参数启动资源管理器：

   ```text
   explorer.exe /select,<目标路径>
   ```

   `/select,` 与目标路径作为同一个命令参数传递，使 Explorer 能够定位并选中目标应用。

2. 启动请求发出后，后台线程等待约 150 毫秒，给 Explorer 留出创建或复用窗口的时间。

3. 从目标路径取得父目录名称。例如：

   ```text
   C:\\Tools\\Demo\\demo.exe -> Demo
   ```

4. 先尝试使用父目录名称精确查找窗口；如果没有找到，再调用现有的模糊标题查找逻辑，以兼容包含“文件资源管理器”等后缀的窗口标题。

5. 找到窗口后调用 `ShowWindow(hwnd, SW_RESTORE)` 和 `SetForegroundWindow(hwnd)`，恢复最小化状态并请求将窗口置于前台。

## 非 Windows 平台

- macOS 继续使用 `open -R <path>`。
- Linux 继续使用 `xdg-open <path>`。
- 前台激活逻辑只在 Windows 编译目标启用。

## 边界与已知限制

### 窗口标题匹配不是唯一标识

资源管理器窗口通常包含当前目录名，因此目录名可以作为轻量级匹配依据。但以下情况可能导致匹配不准确：

- 同时打开多个同名目录；
- 目录名称与其他窗口标题相同；
- Windows 版本、语言或资源管理器设置改变了窗口标题格式；
- 资源管理器使用标签页，多个目录可能属于同一个窗口。

因此该实现是“最佳努力”的窗口激活，不承诺在同名目录场景下精确选择某一个窗口。

### 前台激活受 Windows 限制

`SetForegroundWindow` 受 Windows 前台窗口锁定策略约束。应用可能成功打开目录，但系统仍可能拒绝后台进程抢占用户当前正在操作的窗口。因此这里能够保证的是：发现窗口后尝试恢复并置前，而不是绝对保证始终置前。

### Explorer 创建存在延迟

当前等待时间是固定约 150 毫秒。如果系统繁忙、磁盘较慢或 Explorer 尚未及时创建窗口，第一次查找可能找不到目标窗口；此时打开动作仍已发出，但窗口激活可能失败。

### 目标路径必须可用

目标路径应为有效的文件路径。若路径不存在、无法访问或索引数据本身为空，Explorer 可能打开默认位置或无法选中目标文件；窗口激活逻辑也无法据此判断正确目录。

## 验证建议

在 Windows 上至少验证以下场景：

1. Explorer 已关闭时打开应用所在目录；
2. Explorer 已最小化时打开应用所在目录；
3. Explorer 在前台且已有其他目录窗口时打开；
4. 路径或目录名包含空格、中文；
5. 同时打开两个同名目录时触发该功能。

如果第 5 种场景需要绝对准确地激活指定窗口，应改用 Shell COM 接口或其他能返回具体 Explorer 窗口句柄的方案，而不是继续依赖窗口标题匹配。
