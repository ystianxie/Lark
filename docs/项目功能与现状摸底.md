# Lark 项目功能与现状摸底

> 盘点时间：2026-10-14。范围包括当前工作区代码、README、文档和最近提交（截至 `726ed0f`）。本文描述代码层面的现状，不替代 Windows/macOS 实机验收、安全审计或发布验收；工作区未提交改动也纳入判断。

## 1. 项目定位

Lark 是一个以全局快捷键呼出的桌面效率工具。用户在一个搜索框中查找并执行本地应用、文件、网址、即时计算、剪贴板内容和插件功能。项目当前主要面向 Windows，同时保留 macOS 分支。

当前产品已经超过“启动器 + 索引”的最小骨架，形成了启动器、多个内置面板、插件组件库、通知窗口、首次使用向导和主题系统；插件运行时仍在演进，不能视为完成的第三方生态平台。

## 2. 技术组成与数据边界

- 桌面壳：Tauri 2；Rust 负责窗口、快捷键、索引、剪贴板、文件系统、截图、翻译和插件相关命令。
- 前端：React 19 + Vite；Ant Design、CodeMirror、styled-components 等用于面板和编辑器。
- 本地数据：SQLite 保存应用/文件索引和剪贴板历史；本地配置保存快捷键、索引、外观、Python 解释器及插件配置；IndexedDB 保存前端使用习惯。
- 系统集成：全局快捷键、应用/文件/URL 打开、应用窗口激活、文件管理器定位、剪贴板监听与快速粘贴、屏幕截图、OCR、hosts 编辑和文件跳转。
- 插件目录：用户数据目录的 `plugins/`，开发模式也会读取仓库 `plugins/`。入口描述为 `manifest.json`，可声明 action、panel、url、python 等 workflow 和权限。
- 窗口：主搜索窗口、首次使用向导窗口、通知窗口；通知和主题状态可跨窗口同步。

## 3. 已实现或基本可用的功能

### 3.1 启动器与搜索

- 启动时读取快捷键并注册呼出、剪贴板、划词、文件跳转和截图等快捷键；设置页修改后会校验冲突、替换注册并在失败时回滚。
- 呼出快捷键切换主窗口可见性并聚焦输入框；支持方向键、Enter、Esc、Tab、Alt/Command + 数字选择和打开所在目录。
- 普通搜索合并应用索引、插件 workflow、内置工具、URL、数学表达式和外部搜索入口；结果按使用习惯排序。

### 3.2 应用与文件索引

- Windows 扫描开始菜单、桌面及应用源，macOS 扫描 Applications；支持标题、拼音、首字母和部分路径匹配，展示图标并尝试激活已运行的 Windows 应用。
- 文件索引支持配置搜索根目录、排除目录和扩展名，结果可打开文件或定位到文件管理器；SQLite 批量写入和索引进度事件已存在。
- 文件 watcher 已接入配置目录的变更处理，另有自定义应用索引入口；全量重建仍是可用的兜底流程。索引范围、过滤和平台差异需要实机验证。

### 3.3 剪贴板历史

- 后台监听文本、图片和文件剪贴板，去重后写入 SQLite，记录预览、来源应用、时间和图片数据；按配置数量清理旧记录。
- 剪贴板页支持分页、预览和搜索入口；文本、图片及文件记录可以写回系统剪贴板并模拟 Ctrl/Cmd+V。
- 快速粘贴依赖窗口焦点和平台脚本，Windows 文件拖放格式与 macOS AppleScript 分别实现，不能把跨平台行为视为等价。

### 3.4 内置面板与系统工具

搜索结果可打开以下内置能力：

- 应用设置：快捷键、索引范围/排除项、剪贴板保留、Python 解释器、开机启动和外观。
- 组件库与插件创建/编辑器：查看插件、启停、配置、预览生成文件，创建 JavaScript/Python workflow。
- 翻译：配置多个服务商并调用 Rust 翻译运行时；支持划词入口。
- 截图与 OCR：全屏/区域截图、编辑保存、OCR 后交给翻译或结果页。
- 备忘录、待办、周报：前端本地存储和面板交互已实现。
- hosts 编辑、文件跳转/Listary 跳转、剪贴板页面和 URL/数学计算等即时工具。
- 通知：独立通知窗口，支持成功/信息/警告/错误级别、自动过期、暂停/启用、关闭和按钮 action；插件可在声明权限后发送通知。

### 3.5 首次使用与外观

- 首次启动显示 onboarding 窗口，引导快捷键、索引和基础使用，完成状态写入本地配置。
- 外观支持经典、浅色、深色、磨砂和跟随系统；主题 token 同时用于主窗口、面板和通知窗口。Windows 磨砂效果有原生边界更新逻辑，其他平台使用 CSS/降级背景。

### 3.6 插件运行时

- Rust 扫描 `manifest.json`，返回 id、根目录、manifest、错误和是否可编辑；坏插件单独报告，不阻塞其他插件。重复 id 目前保留先扫描到的记录。
- 创建/更新插件时校验 id、workflow、entry、权限、配置 schema 和允许的文件；组件库支持配置表单及插件文件预览。
- JavaScript entry 通过 Blob module 加载，调用 `activate()`，缓存 runtime 并按 workflow 调用 `execute()`；更新插件时会使旧 runtime 失效并调用 `unmount()`（若提供）。
- context 按 manifest 权限暴露 URL、文件、剪贴板、Python、通知等 API，并提供插件配置读写和当前输入/主题/UI 信息。权限 API 已有宿主侧过滤，但 JS 仍运行在主 WebView 上下文，没有进程级沙箱。
- Python workflow 通过 `run_python_plugin` 调用 JSON Lines runner，支持配置的解释器、请求/响应 id、超时和结构化错误；仓库有 timestamp、curl-to-requests 等示例。依赖安装、虚拟环境和长期进程复用尚未形成完整方案。

## 4. 主要数据流

```text
全局快捷键
  ├─ 主窗口 show/hide + focus
  ├─ 剪贴板/划词/文件跳转/截图入口
  ↓
React 搜索状态
  ├─ 应用/文件 SQLite 查询
  ├─ 内置工具和面板
  └─ manifest workflow → JS runtime / URL / Python
后台任务
  ├─ 应用/文件扫描 + watcher → index_data_v1.sqlite
  ├─ 剪贴板监听 → record_data_v1.sqlite
  └─ 通知管理器 → notification 窗口事件
```

## 6. 当前已确认的问题与限制

1. `get_history_search` 当前仍直接返回全部历史，未按 keyword 过滤，剪贴板搜索结果不符合预期（`src-tauri/src/api/clipboard.rs`）。
2. 插件 JS 通过 WebView 的 Blob module 执行，权限只限制宿主 API，不能阻止插件访问同一页面上下文可见的 Web API；尚无隔离进程或 iframe sandbox。
3. `load_plugins` 对手动安装的 manifest 主要做解析和前端基础检查，严格 schema 校验集中在创建/更新路径；手动安装插件的 entry、workflow 和资源完整性仍可能到执行时才暴露。
4. 插件重复 id 采用先发现者，用户插件、开发目录和打包资源之间的覆盖优先级没有明确的用户可见提示。
5. 文件 watcher、全量扫描、应用图标读取、截图/OCR、磨砂窗口和剪贴板文件粘贴都强依赖操作系统；当前缺少 Windows/macOS 矩阵式验收。
6. 写入 hosts、文本文件和部分系统路径的错误处理仍有历史上的直接 unwrap/外部命令依赖，权限不足或路径异常时需继续收敛为可展示错误。
7. 快速粘贴会暂时覆盖系统剪贴板，随后依赖焦点和内部写入标记恢复；目标应用拒绝粘贴或窗口切换过慢时体验可能不稳定。
8. 前端构建仍有动态/静态导入重复和超过 500 KB 的 chunk；字体和 CodeMirror 使主包较大，启动性能还有优化空间。
9. 当前工作区含未提交的 UI、Rust 配置、主题、通知和文件跳转改动，以及 `show/` 图片和本地可执行文件；这些内容尚未全部形成可发布提交，不能把工作区状态等同于稳定版本。

## 9. 一句话结论

Lark 已具备可运行的桌面搜索、索引、剪贴板、内置效率面板、通知、主题、首次使用向导和 manifest 插件运行时基础；当前主要欠缺的是插件安全隔离与完整生命周期、Python 依赖/长任务管理、跨平台实机验收、搜索边界修复和发布质量体系。
