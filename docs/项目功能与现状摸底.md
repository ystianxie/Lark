# Lark 项目功能与现状摸底

> 审阅范围：仓库当前代码、README、Git 历史和当前工作区状态。本文是初步摸底，不等同于完整测试或安全审计。

## 1. 项目定位

Lark 是一个面向开发者日常工作的桌面快捷启动器，形态类似 uTools：通过全局快捷键呼出搜索框，将本地应用、文件、内置工具和自定义插件统一为可搜索、可执行的条目。

当前实现更接近“本地启动器 + 插件运行时雏形”，而不是已经完成的插件生态平台。

## 2. 技术组成

- 桌面壳：Tauri 2（Rust 后端，支持 Windows/macOS 分支）。
- 前端：React 19 + Vite，Ant Design、styled-components 等用于界面。
- 本地数据：SQLite 保存应用/文件索引和剪贴板历史；IndexedDB 保存前端应用使用习惯。
- 系统集成：全局快捷键、窗口显示/隐藏、打开应用/文件/URL、读取图标、剪贴板监听与模拟粘贴。
- 插件目录：应用数据目录下的 `plugins`，正式入口为 `manifest.json`；工作流可声明动作、页面、URL 或 Python 入口。Rust 加载器已不再读取旧 `info.json`，旧格式仅作为迁移参考。

## 3. 已完成或基本可用的功能

### 3.1 快捷启动主流程

1. Rust 在启动时读取配置中的唤醒快捷键并注册全局快捷键。
2. 按下快捷键时切换 `skylark` 窗口可见性、聚焦窗口并发送 `window-focus` 事件。
3. React 输入框根据输入内容查询并展示结果，支持方向键、Enter、Esc、Tab 及数字快捷选择。
4. 结果列表按应用使用习惯排序；没有本地应用结果时生成 Google、百度、必应、哔哩哔哩、淘宝、京东搜索入口。

### 3.2 应用搜索与启动

- 首次或手动重建时扫描 Windows 开始菜单/桌面，macOS 的 Applications 目录，写入 `app_index`。
- 搜索支持标题、拼音、拼音首字母和部分路径匹配。
- 展示应用图标；启动时按平台调用系统 API/命令。Windows 还尝试检测同名进程并激活已有窗口。

### 3.3 文件搜索

- 扫描固定的用户目录/磁盘，按配置排除目录和扩展名。
- 文件写入 `file_index`，批量提交 SQLite，并通过 `file_index_count` 事件报告进度。
- 输入框按 Tab 可进入“文件搜索”模式，结果可打开文件或在资源管理器/Finder 中定位。

### 3.4 内置工具

- 数学表达式计算（mathjs）。
- URL 识别并使用默认浏览器打开。
- 剪贴板子页面：分页浏览、搜索入口、文本/图片预览、来源应用图标展示。
- 设置子页面：展示快捷键编辑界面和剪贴板保留参数界面（部分保存逻辑尚未完成）。
- 索引重建动作：分别重建文件索引和应用索引。

### 3.5 剪贴板历史

- 后台线程约每秒读取剪贴板，按文本、图片、文件分别计算摘要，去重后写入 SQLite。
- 记录来源应用、创建时间、内容预览及图片数据；文本结果采用“写入系统剪贴板 + Ctrl/Cmd+V”快速粘贴，并通过短时内部写入标记避免该回环重复入库，具体约束见 [`文本结果快速粘贴机制.md`](文本结果快速粘贴机制.md)。
- 超过配置数量时删除旧记录；通知 UI 目前仍是 TODO。

### 3.6 插件/组件雏形

- Rust `load_plugins` 遍历插件目录，读取 `manifest.json`，返回插件 id、根目录、manifest 和单插件错误状态；损坏插件会被跳过，不阻塞其他插件。
- React 将 `workflows`（兼容旧 `workflow`）合并到搜索结果，并兼容 `keywords`/`keyword` 字段。
- workflow 会补充 `type`、`action`、插件根目录等运行信息，但当前仍主要走 `App.jsx` 的旧 `component.type` 分支。
- 支持加载内置 React 子页面，以及从插件目录动态加载 JS 和 CSS；动态脚本仍运行在主页面上下文中，不是安全沙箱。
- 新增 `pluginRuntime.js`，提供按权限生成 API 的 context 雏形；目前尚未完整接入 `activate/mount/execute/unmount` 生命周期。
- 新增 `run_python_plugin` Tauri 命令和 JSON runner 示例，支持指定 Python 解释器、JSON 请求、超时和结构化错误；尚未形成完整的插件级任务注册与依赖管理。
- 插件开发规范已记录在 `docs/插件开发规范.md`，示例插件已从 `info.json` 迁移到 `manifest.json`。

## 4. 主要实现逻辑（简图）

```text
全局快捷键
   ↓
Tauri 窗口 show/hide + window-focus 事件
   ↓
React 输入状态机
   ├─ 空输入/普通输入 → 插件条目 + SQLite 应用索引 + 计算器/URL
   ├─ Tab 文件模式     → SQLite 文件索引
   └─ 选中条目         → open_app / open_file / open_url / 子页面 / 插件 action

后台任务
   ├─ 文件/应用扫描 → index_data_v1.sqlite
   └─ 剪贴板轮询     → record_data_v1.sqlite → 剪贴板页面
```

## 6. 初步发现的问题（仅列现象，不展开原因/方案）

### 高风险或高概率影响使用

1. `get_history_search` 接收 `keyword`，实际直接返回全部历史，剪贴板搜索功能不会按关键词过滤（`src-tauri/src/api/clipboard.rs`）。
2. 应用索引的单条插入 SQL 声明的占位参数数量与传入字段数量不一致；该路径运行时可能失败（`src-tauri/src/utils/database.rs` 的 `insert_app_index`）。
3. `search_app_index`/`search_file_index` 查询失败时返回一个空的默认 `FileIndex`，前端可能把它当成真实结果处理。
4. 设置页面标注“保存设置”，但后端 `save_setting` 仍为 TODO，快捷键输入也没有完成全局重新注册。
5. 插件脚本通过动态 `<script>` 注入且直接执行本地文件，插件隔离、来源校验和错误恢复能力较弱；`pluginRuntime.js` 尚未成为实际唯一入口。
6. `run_python_plugin` 当前接收脚本路径并启动进程，但尚未限制工作目录/环境变量，也未实现真正的 JSON Lines 长驻 runner 和取消机制。

### 中等风险或明显不完整

7. React Tab 切换逻辑使用 `inputBox.length`，但 `inputBox` 是单个 ref，不是输入框集合；进入子页面后的 Tab 行为可能异常（`src/App.jsx:106-113`）。
8. `write_txt`/`append_txt` 等文件操作大量使用 `unwrap`；路径不存在、权限不足或文件不可写时可能导致命令 panic。
9. 文件索引存在“全盘扫描”实现，配置排除项的展开/匹配逻辑仍不完整，首次建立索引可能耗时较长。
10. Windows 应用启动、图标读取依赖外部命令和平台 API；仓库中还存在 `proxy_pool.exe/.pdb`、`target` 等构建产物，发布包边界不清晰。
11. Vite 构建提示存在超过 500KB 的前端 chunk，且 `template.jsx` 同时静态/动态导入，代码分割效果有限。
12. 文本快速粘贴会覆盖系统剪贴板，并依赖窗口隐藏后焦点及时恢复；剪贴板文件复制明确返回“暂不支持文件复制”，图片粘贴、文件粘贴和通知仍在 README/TODO 中。

## 7. 工作区与验证备注

- Git 历史共 14 个提交，最近提交日期为 2025-01-07；项目长期未持续迭代的迹象明显。
- 当前工作区存在大量未提交修改、删除的 `tray.rs`、新增的剪贴板/代理文件及 `target`、`gen` 构建目录。以下结论以“当前文件内容”为主，不能全部归因于 `main` 分支提交版本。
- `pnpm build` 已通过，但有 chunk 体积和动态导入警告。
- 本轮新增插件相关前端代码未有自动化测试；尚未完成“搜索 workflow → 统一插件入口 → context API → JS/Python 结果”的端到端验收。
- `cargo check` 未能完成，失败涉及本机 Cargo 派生依赖缺失/加载权限（如 `zerofrom_derive`、`thiserror_impl`、`serde_derive`），因此暂不能把 Rust 端判定为可成功构建。

## 8. 一句话结论

Lark 已经搭起了“快捷键 + 本地索引 + 剪贴板 + manifest 插件加载”的可运行骨架；插件加载器、manifest 迁移和 Python 调用基础已落地，但统一 JS 生命周期、前端 context/API 实际接入、权限执行和插件级 Python 调度仍处于开发中，尚不能称为完成的插件运行时。

## 9. 关键假设

- 本文把 Git 提交内容视为历史基线，把未提交工作区视为实验/进行中改动，不假设它们都已验证。
- “已完成”表示从代码路径上存在并能形成基本闭环，不代表在 Windows/macOS 各版本上都经过实际验收。
- `manifest.json` 示例位于源码组件目录，尚未证明已安装到应用数据目录后可完成真实端到端执行。
- 未对插件样例、真实系统权限、长时间索引性能和剪贴板兼容性做完整运行测试。
