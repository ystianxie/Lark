# 翻译组件阶段 0 规格

> 状态：已完成（边界与验收基线）
>
> 日期：2026-10-03

## 1. 第一版范围

第一版只解决“文本快速翻译”闭环：手动输入、读取剪贴板文本、显示译文、复制译文，并为后续划词和截图 OCR 保留统一输入接口。

首批语言：自动识别、简体中文、繁体中文、英语、日语、韩语。语言列表采用内部稳定值（如 `zh-CN`、`en`、`ja`、`ko`），显示名称由 UI 提供。

首批 Provider 以小牛翻译为正式内置服务。服务目录预设接口地址、协议、认证方式、语言代码和能力，用户只填写 API Key 及可选的术语库参数。未来允许配置多个服务并行调用，Provider 接口不绑定具体厂商。每个已启用服务独立展示结果，单个服务失败不影响其他结果。AI Provider 作为可选增强入口，不作为快捷翻译的唯一通道。

## 2. 交互边界

- 主入口是翻译 Panel；短文本可由快捷键唤起。
- Panel 支持手动输入和剪贴板填充，默认不自动改写原文。
- 翻译结果提供复制和重新翻译；“替换原文”在剪贴板/划词阶段实现。
- Panel 唤起后应获得输入焦点；关闭后恢复用户之前的工作窗口。
- 窗口和 Provider 运行时尽量复用，不能每次翻译都重新初始化插件或 Python 进程。

## 3. 快捷键与权限

沿用宿主现有全局快捷键设置和冲突检测机制。翻译组件首版只声明：

- `clipboard.read`
- `clipboard.write`
- 必要时使用宿主已有的窗口/快捷键能力

划词读取和系统截图不在阶段 0 授权范围内，等阶段 4/5 明确实现方案后再增补权限。

## 4. 配置与安全基线

配置字段初步确定为：

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `provider` | select | 首个可用 Provider | 当前翻译服务 |
| `source_lang` | select | `auto` | 源语言 |
| `target_lang` | select | `zh-CN` | 目标语言 |
| `request_timeout_ms` | number | 8000 | 单次请求超时 |
| `auto_clipboard` | boolean | false | 是否唤起后自动填充剪贴板 |
| `ai_enhance` | boolean | false | 是否显示 AI 增强入口 |
| Provider 参数 | password/text/select | 空 | API Key、地址、模型等 |

遵循现有插件配置规范：配置由宿主保存，API Key 使用 `password` 字段，插件不写回自身目录。现阶段明文配置只做界面掩码，不视为安全隔离；日志禁止记录 API Key、原文和截图内容。

## 5. 请求数据与错误规则

统一请求形状：

```ts
{
  text: string,
  provider: string,
  sourceLang: string,
  targetLang: string,
  requestId: string,
  signal?: AbortSignal
}
```

统一结果至少包含：`text`、`provider`、`sourceLang`、`targetLang`、`requestId`。错误至少区分：配置缺失、网络失败、鉴权失败、限流、超时、取消、输入过长和服务返回错误。

新请求开始后，旧请求即使晚返回也不能覆盖当前结果。输入为空时不发请求。请求超时后 Panel 必须可继续输入和重试。

## 6. 性能验收基线

以下是第一版的目标值，而不是对外承诺：

- 已打开 Panel 的再次唤起：目标小于 200 ms。
- 本地读取剪贴板并填充：目标小于 100 ms。
- 快速 Provider 首次可见结果：目标小于 2 s；超过 800 ms 显示“正在翻译”。
- 单次请求硬超时：8 s，可在设置中调整到 3–30 s。
- AI Provider 不得阻塞 Panel 首屏，也不能覆盖较新的快速翻译结果。

阶段 3 开始记录分段耗时：唤起、读取输入、请求发出、首个结果、完整结果。这样可以区分进程初始化、网络和模型推理造成的延迟。

## 7. 后续阶段入口条件

- 阶段 1：上述配置字段可以被现有设置宿主渲染并持久化。
- 阶段 2：Mock Provider 能跑通输入、加载、成功、错误、取消和复制交互。
- 阶段 3：真实 Provider 具备超时、取消、旧请求淘汰和错误归一化。
- 阶段 4：剪贴板读写完成后，才实现划词提取和写回。
- 阶段 5：截图 OCR 默认不上传图片；本地/云端 OCR 通过 Provider 决定，并保留识别文本编辑入口。
